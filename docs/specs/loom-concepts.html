Ember · new session type · concept study

Loom: the CLI, woven into something you can see.

A session that looks and types like a terminal. The agent's work shows up as live objects instead of scrolling text: diffs, charts, mocks, running demos, video. You can scrub through it, fork it, and drill into any step. The real claude keeps running underneath, so you lose nothing.

Name: Loom, because it weaves threads (turns, tools, branches) into one fabric. Other names I considered: Stage, Lens, Prism. Command: ember loom. The shortcut gets fixed once you pick a concept.

1 · How nothing gets lost: the twin

Loom does not reimplement Claude Code. It runs the real CLI in a hidden PTY, exactly as an Ember tab does, and reads three structured signals from it. Every keystroke you type in Loom goes into that same PTY. One key flips to the raw TUI at any time. It's the same live session, not a copy.

2 · Feature parity, line by line

Each CLI feature either passes straight through to the PTY or gets a richer control that still sends the same keys underneath.

3 · The interpreter: three tiers, cheapest first

You're right that calling an LLM on every message is too slow and too costly. Most of what Claude Code emits is already structured: tool calls have types and inputs, and markdown has an AST. A model only gets involved for the small part of the output that is plain prose, and even then it upgrades text that is already on screen. It never holds anything back.

TIER 1 · DECLAREDexact

The agent says what to show

The ember-panel MCP grows a show tool (mock, demo, chart, compare, video, page, ask). A one-line system-prompt append tells Claude it's in Loom and the screen is its to direct. This is the strongest signal, because the agent knows what you need to see.

show({ kind:"compare", before:"phone-slow.png", after:"http://localhost:5173/checkout", caption:"LCP 4.8s → 1.9s" })
TIER 2 · STRUCTURAL0 ms · rules

Typed events → typed blocks

Deterministic mapping, no model. Edit → diff. Read → file peek. Bash → terminal tile with exit code. TodoWrite → plan. A markdown table with numbers → chart offer. A localhost URL → live preview. .mp4 → player. mermaid → diagram.

tool_use Edit api/cart.ts → DiffBlock(+9 −23) tool_result Bash exit 0 "42 passed" → TestBlock(42/42 ✓)
TIER 3 · INFERRED~50 ms · local

A small model reads the prose

For finished paragraphs only, async. It runs on-device: a tiny classifier plus an extractor like GLiNER, in ONNX/WASM, the same way Ember already runs Whisper. Its job is labeling and extraction (comparison? plan? decision needed? which entities?), not writing anything new. It doesn't use claude -p: we measured that at a 6–12 s floor.

5 · My pick: they're layers, not rivals

The best version combines them. Stage & Ledger (A) is home, because it keeps the terminal's honesty and gives the agent a screen to direct. Under it runs the River (C) as a scrubbable timeline with real forks. The ledger has Semantic zoom (F). A key flips the stage into Canvas (B) or Document (D) for the whole-session view, and steering queues like Mission control (E).

6 · What makes it feel powerful

Point & ask

Click any pixel on the stage (a bar, a diff line, a button in a mock) and ask about it. The agent gets the element, not a screenshot.

Scrub time

Drag the river back to see the stage as it was. Enter rewinds the real session there.

Fork reality

Try two approaches at once as two real sessions, compared side by side on the shelf.

Steer mid-flight

Type while it works. The message queues as a steering note, and Esc interrupts.

Live demos

The agent starts the dev server and the stage is the app, clickable, with before/after slider.

Mocks on demand

"Show me 3 layouts" gives three live HTML mocks. Pick one and it's the next prompt.

Video & recordings

Screen recordings of a test run or a Playwright trace play inline, scrubbable.

Voice

Ember's voice loop already speaks to sessions. In Loom, speech drives the stage too ("show me the diff").
