Install #

Ember runs on Windows 10 and 11, x64. It is free and open source. It needs no account and installs just for you, without an admin prompt.

DownloadWhat it is
Installer (.exe)The usual choice. Adds Start menu and desktop shortcuts. Uninstall from Windows Settings › Apps.
Portable .zipNo installer. Unzip anywhere and run Ember.exe.
Portable .tar.gzThe same as the .zip, in another archive format.

The links always point at the latest release on GitHub Releases. SHA256SUMS.txt there lets you check the files.

SmartScreen. Releases are not code signed yet, so Windows may warn the first time. Choose More info, then Run anyway. Every build comes from the public source.

Ember replaces the window, not your shell. It runs PowerShell 7 through ConPTY, the same way Windows Terminal does. Your profile, modules, oh-my-posh and PSReadLine work as before. Without PowerShell 7 it falls back to Windows PowerShell.

First run #

The first time Ember opens, it sets itself up in a few seconds:

  1. It finds the agent CLIs you have installed, such as Claude Code or Codex.
  2. It checks that each one answers.
  3. It shares what your agents already know between them (see Shared knowledge).

Then it tells you what it found, and you choose the agent to start with. Start your first session opens a session with that agent, straight on its canvas.

To run setup again, open Welcome & setup from CtrlK.

Your agents #

Ember works with the agent CLIs you already have. It runs each one with its own login and its own subscription, exactly as in any other terminal.

  • Claude Code
  • Codex CLI
  • Gemini CLI
  • Cursor Agent
  • OpenCode
  • Copilot CLI
  • Qwen Code
  • Amp
  • Aider
  • Crush

The agent chip and +

At the top of the sidebar sits a chip with the current agent, for example Claude Code. Next to it is +.

  • + (or CtrlShiftT) opens a new session with the current agent. The agent starts by itself and the session opens on its canvas.
  • Click the chip to switch agents. The next + uses the one you picked. Ember remembers it.
  • Add more agents… at the bottom of the chip's menu opens Settings › Agent. It shows which CLIs are installed and how to install the others.

Claude Code and Codex get the most: their replies, tool calls and objects are read from their own session logs, and Ember docks a shared input box under the canvas. The other agents run in their own screen with Ember's tools available to them.

Sessions and the sidebar #

Each session is a card in the sidebar. It shows the session's name, the model, how full the context is and whether the agent is working or waiting for you.

  • Click a card, or press CtrlTab, to switch. CtrlAlt1–9 jumps to a session by its place.
  • Drag cards to reorder them.
  • Rename with F2 or a double-click. An empty name gives the title back to the agent.
  • CtrlShiftW closes the focused session. CtrlB hides the sidebar.
  • A plain shell, without an agent, is New terminal in CtrlK. Start claude or codex there and it turns into a canvas.

At the bottom left are Todo and Notes. They open as their own pages in the list, outside any session (see Notes and Todo). Opening one again switches to it rather than opening a second copy.

The canvas #

An agent session opens on its canvas. You type in the input box at the bottom and press Enter. The reply appears above it as readable text, not as raw terminal output.

  • The current turn fills the canvas. Earlier turns are a step away: the arrows at the left edge, or CtrlShift↑ / ↓. Each turn keeps its own content.
  • Work in progress (files read, commands run, steps) shows as a short trail while the agent works, then gets out of the way.
  • Visuals. When a picture explains something better than words, the agent draws one: a diagram, a table, a chart, a plan with steps it ticks off. It can also put up a file, an image or a live web page.
  • Copy: select text and press CtrlC. On the canvas that copies; it does not interrupt the agent.
  • The line under the input shows the mode, the model, how full the context is and what the session cost.

Right-click any object for its menu. The box at the top asks the agent about that object, or about the part you clicked, like one node of a diagram. Below it are Copy, Full screen and Place.

Objects in a reply #

A diagram, table or chart that is part of a reply sits in the text. Hover it to see its name and Drag out at the top right.

  • Resize it where it is. Pull any edge or corner. The right edge can grow past the text, out to the edge of the canvas. Pulling the edge lights it up.
  • Drag out takes it out of the reply. Drop it anywhere on the canvas, or at an edge to snap it there (see Placing and snapping).
  • Objects can also go straight onto the canvas when the agent puts them up with a tool. They work the same way.

Placing and snapping #

A placed object stays on screen while the conversation goes on.

  • Move it by its title bar. Resize it from any edge or corner.
  • Snap it by dropping it at the left, right, top or bottom edge. Up to four objects share an edge, and each goes where you drop it: above, between or below the ones already there. A snapped object fills its share of that side, and you resize it from its inner edge.
  • The reply's text moves out of the way, so words never sit under an object.
  • Minimize it to its title bar with the – button, or by double-clicking the bar.
  • When objects overlap, the one you touch comes to the front.
  • Put back (in its menu, or P) returns it to its place in the reply. × removes it from the screen.

Full screen and zoom #

Open any object full screen from its menu, from the button in its title bar, or with Enter when it is selected from the keyboard. Esc or a click outside closes it.

Full screen has a zoom bar at the bottom: −, the zoom level, and +. Click the level to fit again.

  • Ctrl + mouse wheel, or a touchpad pinch, zooms toward the pointer.
  • + and − zoom in and out. 0 fits again.
  • A double-click zooms to 2× where you clicked. Another double-click fits again.
  • When zoomed in, drag to move around.

Canvas or CLI view #

The switch at the top right, Canvas | CLI, shows either the canvas or the agent's own terminal screen. Ctrl` switches too. The switch stays in the same place and size in both views.

Ember remembers your choice and opens new sessions in the same view. Whatever you type reaches the same agent either way.

Sticky notes #

CtrlShiftN in a session drops a sticky note on its canvas, ready to type in. It has a warm colour, so it reads as yours rather than the agent's.

A sticky is a real note. It is saved in your notes, with the date and the session it came from, and it shows up on the Notes page. Move, resize and snap it like any object.

In a plain shell, the same keys open the Notes page.

Notes #

Notes live outside sessions. Open them with the notes button at the bottom left of the sidebar, or All notes in CtrlK.

  • Each note is a Markdown file in Documents\Ember Notes. Edit them in Ember or in any editor.
  • New note starts one. Write meeting notes or ideas there with no session open.
  • Show in the folder opens the folder in Explorer.

Agents and your notes

Agents in Ember can search, read, list, write and add to your notes through Ember's tools. Ask in plain words:

  • "What's in my notes about the release?"
  • "Write a note called Meeting with three points from what we just discussed."

Todo #

One todo list, outside sessions. Open it with the todo button at the bottom left (it shows how many items are open) or CtrlShiftD.

  • Add, tick and reorder items. Ticked items can be cleared into an archive.
  • An item can be handed to a new agent session, which starts with the item as its task.
  • The list is Todo.md in your notes folder, with Todo.archive.md beside it.

Agents can read the list, add items and tick them done:

  • "What's on my todo list?"
  • "Add a todo: rebuild the website."
  • "I finished the release notes, tick that if it's on my list."

Shared knowledge #

Each agent CLI keeps what it knows in its own place. Ember gives them one shared knowledge, so switching from Claude Code to Codex doesn't mean starting from zero.

  • Instructions: how you like to work, in ~/.ember/brain/instructions.md. Ember hands them to every agent it finds, in a marked section of that agent's own instructions file. Text outside that section is never touched, and each file is backed up once first.
  • Memory: one fact per file, in ~/.ember/brain/memory. Agents read it with recall and add to it with remember. On the first sync Ember copies in what Claude Code already remembers.
  • Skills: shared skills, offered to every agent through the skills tool.

Settings › Agent › Shared knowledge shows what is shared, which agents get it, Sync now, and the switch to turn it off. Ember syncs at start and every 15 minutes.

  • In Codex: "Recall what you know about my deploy setup."
  • In any agent: "Remember that I prefer short commit messages."

Computer use #

Agents in Ember can use your Windows desktop: read what is on screen, point at things and click and type. A pointer of Ember's own shows where the agent is working. It glides to each target and dips on every click.

  • look reads the screen as text, with no screenshot. Without a window it lists the open windows. With one, it lists that window's controls with numbers, like #7 [Button] 'Save' (412,88).
  • act runs a whole sequence in one go, one step per line: focus "Notepad", press #7, click #12, settext #3 "hello", type "text", key ctrl+s, scroll -3, run calc, wait "Calculator". Its reply ends with what is on screen afterwards, numbered again, so the agent can plan its next step from it.
  • point shows you where something is, with a short note beside it, and never clicks. It can step through a walkthrough with Next and Done.

STOP is on screen whenever an agent acts. Pressing it halts computer use at once, until you resume it. To turn computer use off altogether, choose Computer use: on / off in CtrlK.

Computer use needs Python 3. Ember installs the few libraries it uses the first time. A locked screen hides every window's controls, so it works only while you are signed in and unlocked.

  • "Open Calculator and work out 12 × 7."
  • "Show me where the Bluetooth settings are."

Ctrl+K and the ember command #

CtrlK (or CtrlShiftP) opens the command line at the bottom of the window. Type to filter, Enter to run. It holds everything Ember can do: new session, new terminal, notes, todo, themes, settings, computer use, and the tools below.

The same commands work from any shell in Ember as ember:

ember                        every command, from the running app
ember new [dir]              new session, in a folder
ember rename <name>          name the session
ember focus <n|name>         switch to a session
ember list                   the open sessions
ember theme [name]           apply a theme
ember settings [tab]         open Settings
ember set <path> <value>     write one setting, e.g. ember set window.opacity 60
ember get <path>             read one setting
ember diag                   Ember's recent log

notes, todo and desk are there as commands too, so scripts and agents can use your notes, your list and computer use from a plain shell.

Terminal tools #

Under every session is a real PowerShell, and the plain terminal has tools of its own.

  • Command blocks. Each command and its output is one block. Ctrl↑ / ↓ move by command. Failed commands are marked red.
  • Splits. A row or a column of panes in one session: AltShift+ and AltShift−.
  • Task runner. Run a project task… in CtrlK lists package.json scripts and Makefile targets.
  • Port rescue. After "address already in use", the command line offers to stop whatever holds the port.
  • Search all sessions… finds text in every session's scrollback.
  • Shell integration (on by default) wraps your prompt without replacing it, so oh-my-posh keeps working. It reports the folder and each command's result. Turn it off in Settings › Behaviour.

Settings and themes #

Ctrl, opens Settings. Type to search every setting at once.

TabWhat's there
LookThemes, fonts, size, window opacity and backdrop (acrylic, mica or none), padding, effects.
MotionOne speed preset for all animation, the caret, session switching, scrolling.
AgentYour agent CLIs, the default agent, shared knowledge, plan usage in the sidebar, the status line on Claude sessions.
BehaviourShell integration and sound.
LabsExperimental features, such as the phone link.

Day and night

The sun and moon in the title bar switch between Ember Night and Ember Day, a light theme on warm paper. Everything in Ember follows: the canvas, objects, sticky notes, the Todo and Notes pages, menus and setup. More themes are in Settings › Look and in Change theme… in CtrlK. Diagrams and documents the agent draws take the theme's colours.

Phone link (Labs) #

Off by default, and experimental. Turn on Labs in Settings, then choose Connect your phone in CtrlK and scan the QR code with the Ember phone app.

The phone then shows your sessions, lets you read the replies, zoom into diagrams and send messages. One phone can be linked to more than one computer. Traffic goes through a relay that Deep Answer Labs runs, encrypted between your devices. Unless you're trying it out, leave Labs off.

Files and privacy #

~/.ember/desk.log, desk.haltComputer-use log, and the marker that holds STOP.
~/.ember/diag.logDiagnostics. Read the end with ember diag.
Documents\Ember Notes\Your notes, Todo.md and Todo.archive.md.

Set EMBER_HOME to keep Ember's files somewhere other than ~/.ember, and EMBER_NOTES_DIR for the notes.

Ember has no account and no telemetry. Your work goes wherever your agent CLI already sends it. The calls Ember makes on its own belong to features you can see and turn off: the plan-usage poll and the phone relay (Labs).

Troubleshooting #

Windows warned me about the installer.

Releases aren't code signed yet. Choose More info, then Run anyway. Every build comes from the public source on GitHub.

A new session shows a shell instead of the agent.

The agent CLI isn't installed, or isn't on your PATH. Open Settings › Agent to see what Ember found, or run Welcome & setup from CtrlK.

The canvas stays empty while the agent works.

Switch to the CLI view (Ctrl`) to see the agent's own screen. If it is asking something there, answer it. Agents other than Claude Code and Codex show their own screen by design.

Text looks garbled or doubled, as if another window shows through.

That is the window behind showing through the glass. Raise Opacity in Settings › Look, or set Backdrop to acrylic or mica.

Ember feels slow or the laptop runs hot.

Choose the fast preset in Settings › Motion and keep Shed effects when slow on. A 4K display at a high refresh rate costs the most.

Computer use says it's unavailable.

Install Python 3 from python.org and try again. HALTED means STOP is on: resume it from the STOP button or with desk resume. A locked screen hides every window's controls.

Stray characters appear when I move the mouse.

A program exited without turning off mouse reporting. Run Reset terminal modes from CtrlK.

Something else is wrong.

Run ember diag for Ember's recent log, and open an issue on GitHub with it.
